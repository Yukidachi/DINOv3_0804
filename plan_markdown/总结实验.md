# Cityscapes 知识蒸馏实验总结与后续数据分析方案

版本：2026-08-27

本文汇总当前已完成的 T1、S2-0、A0-FT、K4、R5 和 H 组结果，重点回答两个问题：

1. `OS=16 + R-ASPP` 的空间分辨率和上采样是否是小目标性能不足的主要原因；
2. MobileNetV2 的模型容量是否已经成为学生性能上限。

本文只使用 `dev_local` 结果进行分析。`test_local` 的 500 张图像仍是最终留出集，在候选、协议和分析方法冻结前不得查看，也不得用于调参或选择解释。

## 1. 固定口径与证据边界

固定协议为：`train_local/dev_local/test_local=2530/445/500`，训练 crop 为 `512×1024`，dev 使用 `1024×2048` 单尺度推理，学生和教师均使用 `OS=16`，学生为 MobileNetV2+R-ASPP，教师为 DINOv3 ConvNeXt-T+R-ASPP。结果 JSON 是权威来源，Excel 只作人工汇总。

现有结果只能按原实验中已经登记的 seed、paired-bootstrap 和梯度门解释。后续新增诊断若需要新的数值阈值，必须在运行前标为“前瞻性规划阈值”，不得反向改写既有结论。

### 1.1 当前主要结果

| 实验 | 协议/seed | dev mIoU | small-object mIoU | 当前允许的解释 |
|---|---|---:|---:|---|
| T1 | 教师，3 seed | `0.776024 ± 0.002086` | `0.790174 ± 0.003894` | 教师参考上限，不是学生容量对照 |
| S2-0 | V2 scratch，3 seed | `0.495653 ± 0.005220` | `0.391439 ± 0.008099` | V2 端到端基线 |
| A0-FT | A0 初始化后纯 CE，3 seed | `0.55215 ± 0.01022` | 总结中未给出汇总值 | 分阶段初始化的下游效果 |
| K4 | A0 初始化+logits KD，3 seed | `0.57049 ± 0.00582` | `0.47086 ± 0.02522` | 当前最强三 seed V2 候选 |
| R5 | feature+R2+logits，seed=42 | `0.573653` | `0.489157` | 单 seed 强筛选信号，不能与 K4 作稳定优劣结论 |
| H0 | ReLU6 anchor，3 seed | `0.560413 ± 0.002410` | `0.466036 ± 0.001349` | H 组内部 matched anchor |
| H1/H2/H3 | Hardswish，均 seed=42 | `0.516091/0.523697/0.522735` | `0.407219/0.377401/0.395691` | 负向筛选结果，不是三 seed 稳定排序 |

由此可以确认：蒸馏显著改善了 S2-0，但 K4/R5 的小目标指标仍明显低于 T1。这个事实支持“存在未解决的学生侧瓶颈”，但不能单独区分解码器、特征分辨率、backbone 表征质量和模型容量。

## 2. 对两个猜测的科学判断

### 2.1 猜测一：OS=16 与 R-ASPP 上采样伤害小目标

这个猜测具有合理性，但目前只能称为待验证的机制假设。

在 `1024×2048` 输入上，OS=16 的主特征空间约为 `64×128`；一个小目标在该空间中可能只覆盖很少的 feature cell，经过 R-ASPP 和上采样后，边界和细粒度类别容易被平滑。训练 crop 为 `512×1024` 时对应空间约为 `32×64`，小目标还可能受到随机缩放和裁剪的进一步影响。因此，按目标在 feature map 上的覆盖面积、边界宽度和预测错误位置分析这一方向是合理的。

但“学生和教师都为 OS=16”并不能推导出“OS=16 不是原因”，也不能推导出“OS=16 已解释全部差距”。两者虽然具有相同的输出步长，仍可能在以下方面不同：

- DINOv3 ConvNeXt-T 的中间表征、通道数和有效语义容量更强；
- T1 的 R-ASPP head 是在教师特征上训练得到的，学生 head 只处理 MobileNetV2 特征；
- 教师 feature 的空间定位、上下文和类别分离能力可能使同样的 OS=16 网格更可解码；
- K4/R5 还改变了初始化和监督信号，不能把它们与 T1 的差值归因给 decoder。

因此，若教师也在相同 OS=16 下达到较高小目标 mIoU，最直接的结论是：**OS=16 可能造成共同的空间信息上限，但学生与教师的剩余差距不能由上采样单独解释；学生特征在相同网格上的可解码性必须同时检查。**

现有证据还显示，R2 空间关系和 logits KD 能改善 small-object mIoU，说明问题不只是输出尺寸固定造成的不可恢复错误；另一方面，H2/H3 改变学生激活后没有恢复小目标性能，也不支持“换激活即可解决分辨率问题”。

### 2.2 猜测二：MobileNetV2 容量不足

这个猜测同样合理，但当前证据不能证明 MobileNetV2 本身已经达到容量上限。

支持该猜测的事实是：T1 与学生之间仍有较大 mIoU 和 small-object mIoU 差距；S2-0、K4 和 R5 的改进说明监督和蒸馏可以释放性能，但没有接近教师。A6 完整教师空间对学生过难，也说明教师表征与学生可承载空间存在容量或优化难度差异。

不能据此直接下结论的原因是：

- K4 与 R5 的学生损失、初始化和多项蒸馏目标形成了复杂的 Pareto 折中；
- K4 使用 A0 分阶段初始化，R5 目前只有一个 seed，不能把候选差距解释成纯容量效应；
- feature loss 非零可能来自目标空间不完全可拟合，也可能来自损失权重和优化轨迹；
- 现有结果没有同一训练协议下的容量梯度对照。

严格地说，只有在保持数据、head、loss、优化器、训练步数和 seed 全部匹配，仅改变一个预先登记的容量因素后，性能随容量增加而重复改善，且教师差距同步缩小，才能支持容量限制假设。

## 3. 现有数据的后续处理

### 3.1 第一阶段：生成可审计的总表

从各运行目录的 `metrics.json`、`dev_metrics.json` 和 `dev_per_image_confusion.jsonl` 生成一张只读汇总表。每行至少包含：实验编号、seed、best step、mIoU、mAcc、pixel Acc、small-object mIoU、boundary F1、19 类 IoU、结果文件路径、模型 hash 和 `test_local_evaluated`。

必须把以下三种证据分开：

1. 三 seed 的 `mean ± sample std`，表示训练 seed 波动；
2. 同一 seed 的 445 张图像 paired-bootstrap，表示固定 checkpoint 的图像层不确定性；
3. 单 seed 或不同协议比较，只能作为筛选或描述性证据。

建议绘制：总体 mIoU 与 small-object mIoU 散点图、到 T1 的总体/小目标 gap 图、boundary F1 与 small-object mIoU trade-off 图、各运行 dev 曲线。单 seed 点必须用不同标记，不能和三 seed 均值混成同一统计量。

### 3.2 第二阶段：逐类和逐图分析

对每个正式候选提取：

- 19 类 IoU、每类 false negative 和 false positive；
- GT 中各类有效像素数；
- 每张图的 confusion matrix、有效像素数和预测 mIoU；
- 小目标相关类别在每张图中的 GT 像素数、预测像素数和错误像素数；
- 与 T1、S2-0 的同图差值。

“small-object mIoU”必须追溯到实际指标定义。若当前定义只是预先指定的类别集合，应同时报告类别集合和每类结果；不能把“small-object 类别”误称为真实实例级小目标。若使用 `instanceIds` 或实例标注，应在文档中明确其来源、面积单位和是否与训练标签对齐。

逐图可视化优先选择：S2-0、K4、R5（R5 标记为单 seed）和 T1 的同一批 `dev_local` 图像，并保存原图、GT、预测、差异 mask、边界错误 mask。优先查看三类样本：

1. T1 正确而学生错误的小目标；
2. 学生和教师均错误的小目标；
3. 学生与教师均正确但边界不同的目标。

如果大量样本属于第 2 类，更像共同的空间/标签/输入限制；如果主要属于第 1 类，才更支持学生表征或容量问题。这个分类是诊断证据，不是因果证明。

### 3.3 第三阶段：按空间覆盖率分层

对每个 GT 实例或语义连通区域，计算：

- 原图面积和包围盒尺寸；
- 在 OS=4、OS=8、OS=16 网格上的覆盖面积；
- 覆盖 feature cell 数量及其比例；
- 目标边界宽度与目标尺寸的比值；
- 该目标区域内 T1、S2-0、K4、R5 的 IoU、召回和边界 F1。

若只有语义 mask 而没有可靠实例标注，则使用连通组件只能作为 proxy，必须标记为“语义连通区域分析”，不能称为真实对象级分析。

建议按面积或 feature-cell 覆盖率分为若干固定区间，区间必须在查看模型结果前登记。每个区间报告样本数、目标级召回、区域 IoU、边界 F1 和模型间差值。重点观察：

- 学生与教师差距是否随 OS=16 覆盖 cell 数减少而扩大；
- K4/R5 相对 S2-0 的收益是否集中在小覆盖率区间；
- 教师是否也在最低覆盖率区间明显退化。

若 T1 在最低覆盖率区间仍明显优于学生，说明相同 OS=16 网格上的特征可分性/解码能力差异重要，不能只归因于上采样。若 T1 和学生都在该区间同步崩溃，才增强“共同空间瓶颈”的证据。

## 4. 两个最小验证实验

以下均为新的前瞻性实验，不能回写为原 T1、K4、R5 或 H 组的既有因果结论。每项只改变一个因素，并使用 matched `seed=42/3407/260805`、相同初始化规则、batch、增强、80k steps、checkpoint 规则和 dev 评估。

### 4.1 验证空间分辨率/解码器假设

登记一个单变量的 spatial control：保留 MobileNetV2、参数初始化、监督损失和训练协议，只改变一个已明确实现的输出空间因素，例如在不改变 backbone 其他结构的前提下比较 `OS=16` 与预先登记的更高分辨率输出路径，或比较严格对齐的 decoder 上采样路径。

不得同时改变 backbone、R-ASPP 类型、输入 crop、loss 或数据增强。若更改 OS 必然改变 dilation、feature tap 或 head 输入，则必须把这些耦合变化写入协议，不能称为“只改变上采样”。

主指标为总体 mIoU、small-object mIoU、按覆盖率分层的目标召回/IoU 和 boundary F1；同时记录每层 feature shape、参数量、MACs、显存和真实推理延迟。效率只有在 `efficiency.json` 实际完成测量后才能报告。

判定逻辑：

- 更高分辨率只改善最低覆盖率区间和 small-object 指标，且总体指标不劣于 matched anchor：支持空间瓶颈假设；
- 更高分辨率只提高总体指标，而 small-object gap 不缩小：不支持“主要是小目标分辨率问题”；
- 教师/学生在相同 OS=16 网格上的特征可分性差异显著，而更高分辨率收益很小：应把学生表征/容量列为优先原因；
- 若结果不稳定或改动不止一个空间因素：停止因果解释，保留为探索性结果。

若当前协议没有预注册的空间实验阈值，所有“改善多少才算有效”的数字必须在运行前另行登记为前瞻性规划阈值，不能使用它们重新解释旧结果。

### 4.2 验证 MobileNetV2 容量假设

登记一个单因素容量 control：保留 MobileNetV2 的 block 类型、R-ASPP、输入输出协议和训练流程，只使用一个预先定义的宽度或通道容量变体。不要开展宽度、深度、激活、head 和 loss 的组合网格。

至少设置：

| 条件 | 目的 |
|---|---|
| matched V2 scratch CE | 观察容量对纯监督上限的影响 |
| matched V2 distilled condition | 观察容量增加后能否继续吸收教师知识 |
| T1 reference | 计算教师 gap，不参与学生训练 |

若资源只允许最小实验，优先完成 scratch 条件；只有 scratch 条件呈现清晰容量趋势后，才运行蒸馏条件。每个条件使用三个 matched seeds，并报告 mIoU、small-object mIoU、boundary F1、19 类 IoU、teacher gap、参数量、MACs、显存和延迟。

判定逻辑：

- 容量增加在三个 seed 上方向一致，且总体 mIoU 与 small-object mIoU 同时改善、到 T1 的 gap 缩小：支持容量限制；
- 只改善总体 mIoU，small-object 和 boundary 不改善：支持一般拟合能力影响，但不支持容量是小目标问题的主要原因；
- scratch 随容量改善、蒸馏条件不改善：容量是必要但不是当前蒸馏瓶颈，需检查目标空间或优化冲突；
- 两种条件均无稳定改善：在测试范围内不支持“容量不足是主要原因”；
- 只有单 seed 或 paired-bootstrap 正向而训练 seed 方向不稳定：只能写筛选信号，不能下稳定结论。

## 5. 测试、统计和停止规则

新增实验开始前必须先完成数据与产物审计：确认 split 数量和 hash、`test_local` 未被加载、教师冻结且为 eval、ignore index 不参与 loss、feature shape 正确、所有 loss/gradient finite、best checkpoint 只由 `dev_local mIoU` 选择。

新实验先做一批 forward/backward 和短程 smoke test，再进行三 seed 正式训练。每次运行保存配置、初始化/教师/数据 hash、完整 loss 曲线、梯度日志、逐图 confusion、best checkpoint、重载复现结果和 `test_local_evaluated=false`。

停止任一分支的条件为：

- 实现审计失败、出现非 finite 或 split 泄漏；
- 实际改变了多个未登记因素；
- 预注册的效果/梯度/稳定性门未通过；
- 三 seed 结果无法区分于训练波动，且没有预注册的机制价值；
- 必须查看 `test_local` 才能决定下一步；
- 结果只能支持事后提出的阈值。

现有实验中已经登记的阈值继续沿用。例如 K 组、R 组和 H 组的 paired-bootstrap、seed 波动和梯度门只能用于各自已注册问题。新增 spatial/capacity control 的阈值必须在实验前登记，并明确标注为前瞻性规划阈值。

## 6. 推荐执行顺序

1. 锁定现有 dev 结果表、文件 hash 和证据等级，不查看 `test_local`。
2. 先完成逐类、逐图、边界和目标尺寸/feature-cell 覆盖率分析。
3. 生成 T1、S2-0、K4 和 R5 的同图可视化；R5 单独标记为 seed=42。
4. 根据“教师也失败”还是“教师正确而学生失败”的比例，决定优先做 spatial control 还是 capacity control；若两者都明显，先做空间单变量对照。
5. 完成一个空间 matched control 后再决定是否进行容量 control，避免同时改变两个原因变量。
6. 容量 control 只采用一个预先登记的容量变体，三 seed 完成后再解释 teacher gap。
7. 在候选和分析规则全部冻结后，才按原协议统一进行一次 `test_local` 评估。

## 7. 最终结论边界

当前最稳妥的总判断是：**蒸馏已显著提升 MobileNetV2，但学生仍存在明显的小目标和总体性能差距；OS=16/R-ASPP 的空间恢复能力与 MobileNetV2 的表征容量都是合理候选原因，现有结果尚未完成二者的因果分离。**

现阶段不能声称：

- OS=16 或 R-ASPP 上采样单独造成了学生小目标弱；
- 因为教师也是 OS=16，所以空间分辨率不是问题；
- T1 与学生的差距已经证明 MobileNetV2 容量不足；
- R5 稳定优于 K4；
- H1/H2/H3 的单 seed 结果代表跨 seed 的激活函数结论；
- H 组已有部署效率或 Pareto 结论，因为效率产物尚未启用；
- 任何未在 JSON 中报告的具体类别弱点；
- `test_local` 上的性能或其可用于调参。

后续工作的停止标准不是“找到一个看起来合理的解释”，而是：在不打开 `test_local` 的前提下，完成可审计的 dev 分层分析，并通过 matched 单变量实验使空间瓶颈、容量瓶颈或“二者均非主要原因”至少有一个可证伪、可重复的证据链。

# Cityscapes 知识蒸馏 R 组训练部分总结

更新日期：2026-08-21

## 1. 总结结论

R0-R5 已完成首轮筛选，R2/R3 已扩展至 `seed=42/3407/260805`，R5 已完成 `seed=42` 门控运行，共 11 个 80k optimizer-step 运行。所有运行的最佳 checkpoint、dev 指标、逐图 confusion matrix、训练历史和梯度日志完整，`test_local` 均未查看。R2/R3 的结论使用三 seed，R5 的结论仍严格限于单 seed：

1. **R0 精确复现 K1，R 组对照链成立。** R0 与 K1 `seed=42` 的最佳 mIoU 均为 `0.522120`，最佳模型 state hash 相同，首 batch 两个 rank 的 CE、feature loss 和样本审计字段在 `1e-6` 容差内完全一致。
2. **R2 `lambda=0.3` 的增益在三 seed 上复现，但增益幅度低于 seed=42 的单次结果。** R2 mIoU 为 `0.53275 ± 0.00601`，相对同 seed K1 的 mIoU 差值为 `+0.006816/+0.009327/+0.005246`，均值 `+0.007130 ± 0.002059`；三次均为正。R2 是当前已完成三 seed 的最佳关系主线。
3. **不能把 R1 与最佳 R2 的差距直接解释为“跨图关系不如图内关系”。** R1 与 R2 `lambda=0.03` 的 mIoU 分别为 `0.528969/0.528936`，几乎相同；最佳 R2 使用的是十倍权重 `lambda=0.3`。因此 R1/R2 最佳值的差异同时混合了关系类型和有效梯度尺度。
4. **R1 loss 不是“没有下降”，而是快速下降后进入带噪平台。** raw R1 loss 从 epoch 1 的 `1.3003` 降至 epoch 40 的 `0.0909`，最终为 `0.1261`；252 次相邻 epoch 变化中有 128 次上升。它说明跨图关系目标具有明显 batch 依赖和后期波动，但不能证明“图像关系在分割任务中不明显”。
5. **现有结果更支持“R1 的跨图关系约束弱”，而不是“关系知识整体无效”。** R1 相对 R0 的 mIoU 增量为 `+0.006849`，但 paired-bootstrap 95% CI `[-0.001215,+0.015468]` 跨 0；其后期 relation/feature 有效梯度比例多低于预设 `0.05` 下限。相反，R2 `lambda=0.3` 在大部分固定审计点进入 `0.05-0.20` 目标带，并获得更大的 mIoU 和小目标增益。
6. **R1 与 R2 在三 seed 上未显示可加性。** R3 mIoU 为 `0.52839 ± 0.00347`，R2 为 `0.53275 ± 0.00601`；R3-R2 的 mIoU 差值为 `-0.007323/-0.003103/-0.002651`，三次均为负，均值 `-0.004359`。因此在当前 `R1=0.03/R2=0.3` 配置下，两类关系没有显示主指标互补。
7. **R2/R4 支持 feature MSE 对关系蒸馏具有辅助作用，但不能把全部差值归因于纯协同增益。** R4 移除 feature MSE 后，mIoU 从 R2 的 `0.539689` 降至 `0.525697`，差值 `-0.013992`；boundary F1 下降 `-0.039601`。同时 R4 raw R2 loss 最终降至 `0.0134`，而 R2 保持在 `0.1654`，说明 relation-only 更容易得到低关系残差，却没有转化为更高分割性能。严格的“交互量”仍需要 CE-only、feature-only、relation-only、feature+relation 的同组三 seed 2×2 对照。
8. **R5 `seed=42` 显示 feature+R2+logits 的组合具有很强的单 seed 增益，但仍不能作为稳定结论。** R5 mIoU 为 `0.573653`，相对同 seed R2 增加 `+0.033964`，相对同 seed K3 增加 `+0.019663`；逐图 paired-bootstrap 的 R5-R2 95% CI 为 `[+0.025654,+0.042453]`。R5 还高于 K4 三 seed均值 `0.57049`，但这是 R5 单 seed 对 K4 三 seed均值的非配对、协议不同比较，不能宣称 R5 已超过 K4。
9. **R 组当前可以结束主线并进入 D 组。** R2/R3 已完成预定三 seed扩展，R5 已通过 seed=42 的 mIoU、paired-bootstrap 和梯度门；R5 是否扩展三 seed可作为后续最终候选复验，不是进入 D 组的前置条件。R1 的当前配置不扩展，R4 按原协议保持单 seed诊断；R0 由 K1 三 seed提供等价锚点。

## 2. 固定训练协议

R0-R5 复用 K 组数据、教师、学生、初始化、优化器和评估协议；R5 额外启用 K 组冻结教师的 pixel-logit KD：

| 项目 | 固定值 |
|---|---|
| `train_local/dev_local/test_local` | `2530/445/500`；`test_local` 当前未查看 |
| 数据清单组合哈希 | `033161572be28a6de295e0c5dfb62d83cd4d0a18b6039321347c58ab28b9d3c2` |
| 教师 | T1 `seed=3407`，DINOv3 ConvNeXt-T + R-ASPP，冻结 |
| 教师 checkpoint SHA-256 | `73cb1d3161c746d1b4ea30918ec6a1f0de5e3a4952c000cf85ddf95f3ccaddeb` |
| 学生 | MobileNetV2 + R-ASPP，`weights=None`，`output_stride=16` |
| 当前 seed | `42`；未来扩展使用 `42/3407/260805` matched seeds |
| 初始化 | 复用 K 组同 seed shared scratch state；R 组不生成新初始化 |
| 预算 | 80,000 optimizer steps，global batch=8 |
| 优化器 | SGD，lr=0.01，momentum=0.9，weight decay=`1e-4`，poly power=0.9 |
| 辅助项 | 前 4000 optimizer steps 线性 warm-up |
| feature KD | A0 固定 StandardScaler+PCA，OS=4/8/16 等权 MSE，`lambda_feat=1.0` |
| R1 | 物理 batch=4 的 masked-GAP `4x4` 跨图 signed-cosine matrix MSE |
| R2 | 每图 masked `8x16` token 的 `128x128` 空间 signed-cosine matrix MSE |
| checkpoint 选择 | 固定跑满 80k，仅按 `dev_local` mIoU 选择最佳 checkpoint |

各组唯一变量为：

| 实验 | 损失组成 | 关系权重 | 目的 |
|---|---|---:|---|
| R0 | `CE+feature` | 无 | 复现 K1，建立 R 组锚点 |
| R1 | `CE+feature+R1` | `lambda_r1=0.03` | 跨图关系增量 |
| R2-low | `CE+feature+R2` | `lambda_r2=0.03` | 初始梯度校准；非最终候选 |
| R2 | `CE+feature+R2` | `lambda_r2=0.3` | 图内空间关系候选 |
| R3 | `CE+feature+R1+R2` | `0.03/0.3` | 两类关系互补性 |
| R4 | `CE+R2` | `lambda_r2=0.3` | 移除 feature KD 的欠约束诊断 |
| R5 | `CE+feature+R2+logits` | `lambda_feat=1.0/lambda_r2=0.3/lambda_logit=0.5` | 三类损失组合，R 组最终候选门控 |

R2-low 的 relation/feature 梯度比例全程为 `0.00337-0.01175`，没有达到预注册目标 `0.05-0.20`，因此按计划将 R2 权重校准到 `0.3`。Excel 只录入最终选定的 R2 `lambda=0.3`，未录入 R2-low。

### 3.3 对“关系知识能否提高性能”的回答

可以作出**受控范围内的支持性结论**：R2 空间关系在三个训练 seed 上都高于同 seed K1/R0，mIoU 差值全部为正，均值 `+0.007130`；这说明在当前 MobileNetV2、Cityscapes、本地划分、教师和损失权重协议下，关系蒸馏能够提高 dev 分割性能，且不是只由 seed=42 的偶然领先造成。

但应限定为“R2 空间关系提供了稳定的增量证据”，不能泛化成所有关系定义都有效：R1 的单 seed paired CI 跨 0，R3 三 seed没有优于 R2，R4 relation-only 也没有显示稳定主指标增益。R5 的 `seed=42` 进一步表明空间关系与 logits KD、feature MSE 联合时可能产生更大的增益，但 R5 尚未完成三 seed，因此目前是强候选而不是稳定的最终结论。

## 5. R1 的关系损失曲线说明什么

### 5.1 R1 有明确下降过程

| 时点 | optimizer step | raw R1 loss | feature loss | CE |
|---|---:|---:|---:|---:|
| epoch 1 | 317 | `1.30029` | `3.95191` | `1.46638` |
| epoch 13 | 4121 | `0.15242` | `1.79980` | `0.58780` |
| epoch 40 | 12680 | `0.09086` | `1.34985` | `0.42064` |
| epoch 80 | 25360 | `0.10501` | `1.18877` | `0.35706` |
| epoch 160 | 50720 | `0.12421` | `1.06006` | `0.27234` |
| epoch 253 | 80000 | `0.12609` | `0.99805` | `0.22504` |

所以准确描述是：**R1 在 warm-up 前后快速消除了大部分初始关系残差，约 epoch 40 后进入非单调平台，并非从头到尾没有下降。** 训练全程 finite，也未触发 relation/CE 连续三次超过 2 倍的停止门。

### 5.2 波动不等于关系不存在

R1 基于当前物理 batch 的 4 张图构造 `4x4` 跨图矩阵，不使用梯度累积后的 batch=8，也不跨 step 缓存样本。因此每个 batch 的图像类别组成、场景和增强都会改变 target matrix；在小物理 batch 下，raw loss 天然比固定图内 token 关系更受采样影响。R1 step 级 raw loss 的变异系数约为 `1.16`，R2 `lambda=0.3` 约为 `0.39`，与这一解释一致。

此外，R1 在固定审计点的 relation/CE cosine 接近 0，relation/feature cosine 在 step 40000 出现 `-0.116`，其 relation/feature 有效梯度比例从 step 4000 的 `0.0500` 降至 step 80000 的 `0.0243`。这支持“当前 R1 信号后期偏弱且部分状态与 feature 方向不一致”，但审计只覆盖固定 batch/tap，不能外推为全参数或全数据冲突。

### 5.3 对问题 1 的回答

当前证据不能推出“图像关系在 segmentation 中不明显”。更严格的结论是：

- **跨图像全局关系 R1**：有小幅单 seed 增益，但图像层 paired CI 跨 0、后期梯度弱、raw loss 波动大；当前 `lambda=0.03` 配置不进入三 seed 主线，若论文必须研究 R1，应先做新的权重校准；
- **图内空间关系 R2**：在权重校准后获得较大 mIoU 和 small-object 增益，说明空间关系对 segmentation 可能有用；
- R1 使用 4 张图的全局 GAP 关系，容易丢失像素布局和类别局部结构，因此它弱于 R2 与 dense prediction 的空间归纳偏置相符，但仍只是机制解释，不是由单 seed 直接证明的普遍规律。

### 5.4 是否把 R1 的 lambda-rel 直接调到 0.3

**不建议立即把 R1 的正式实验权重从 `0.03` 直接改为 `0.3`。** R1 当前确实表现出关系项偏弱：固定审计点的 relation/feature 比例从 `0.0500` 降到 `0.0243`，但这只能说明 `lambda_r1=0.03` 的有效梯度后期偏小，不能证明 R1 在 `0.3` 下会稳定有效。R2 的 `0.03 -> 0.3` 是经过关系定义、valid-pair reduction 和梯度门检查后的校准结果，不能把同一个数值直接移植到 R1。

若跨图关系是论文核心问题，建议按原 R 组预注册候选做**短程校准/审计**，优先比较 `lambda_r1=0.06`，同时记录 R1/feature 和 R1/CE 比例；只有在实现和梯度门稳定、且有效比例仍明显低于 `0.05` 时，才另行登记 `0.3` 的探索性运行。`0.3` 相对当前权重是十倍放大，按近似线性外推可能使 R1/feature 比例达到约 `0.18-1.01`，其中后段可能超过目标带并增加与 CE 或 feature 的竞争风险，因此不能直接作为正式三 seed 配置。

当前推荐顺序是：

1. R2 `lambda=0.3` 与 R3 先完成三 seed，确认空间关系主线和组合关系结论；
2. 若需要回答跨图关系本身，再做 R1 `lambda=0.06` 的短程梯度校准，而不是立即补当前 `0.03` 的三 seed；
3. 只有校准结果显示 `0.06` 仍不足且没有触发关系/CE 停止门，才考虑预注册 R1 `lambda=0.3` 的单 seed 探索；
4. 在没有上述校准前，不把 R1 `0.3` 与 R2 `0.3` 的结果直接作关系类型优劣比较。

## 6. R2、R3 与 R4 的机制解释

### 6.1 R2 的增益依赖有效梯度尺度

R2 `lambda=0.03` 的 relation/feature 有效梯度比例为 `0.00337-0.01175`，全程低于目标下限；其 mIoU 与同权重 R1 几乎相同。提高到 `lambda=0.3` 后，固定审计点比例为 `0.0468/0.1040/0.0698/0.0690/0.0634`，除 warm-up 边界附近外进入预设目标带，mIoU 相对 R2-low 增加 `+0.010753`。

这说明当前结果不只是“R2 定义优于 R1”，也包含权重校准收益。若未来要严格比较关系类型，应增加 R1 的预注册权重校准，而不能直接用 `R1(0.03)` 对比 `R2(0.3)` 后把全部差异归因于类型。

### 6.2 R3 未显示两类关系可加

R3 使用已经筛选的 `R1=0.03` 和 `R2=0.3`，combined relation/feature 有效梯度比例处于 `0.04118-0.11356`，没有梯度爆炸，但 mIoU 低于 R2。R3 中 raw R1 loss 最终仅 `0.0439`，明显低于 R1 单独训练的 `0.1261`，而 raw R2 loss 与 R2 几乎相同，说明 R2 主导的优化轨迹能够同时压低 R1 残差，但更低 R1 残差没有转化为更高 mIoU。

### 6.3 R2/R4 支持 feature MSE 的辅助作用

| 指标 | R2：`CE+feature+R2` | R4：`CE+R2` | R2-R4 |
|---|---:|---:|---:|
| mIoU | `0.539689` | `0.525697` | `+0.013992` |
| mAcc | `0.607588` | `0.602368` | `+0.005220` |
| pixel accuracy | `0.917864` | `0.910002` | `+0.007862` |
| small-object mIoU | `0.440110` | `0.423396` | `+0.016714` |
| boundary F1 | `0.441265` | `0.401664` | `+0.039601` |
| final raw R2 loss | `0.16538` | `0.01338` | `+0.15200` |

R4 更容易把关系矩阵拟合到很低残差，却在所有五项 dev 指标上低于 R2，尤其边界指标差距最大。最合理的解释是：feature MSE 提供逐点表示锚点，防止学生仅通过一种对关系矩阵友好、但对像素分类不充分的表示来降低 R2；二者联合形成更受约束的折中解。

但 R2-R4 同时包含 feature MSE 的主效应和 feature×relation 交互，不能仅凭两格对照将 `+0.013992` 全部称为“协同增益”。若需要正式估计交互量，应在 matched seeds 下使用 K0=`CE`、R0=`CE+feature`、R4=`CE+R2`、R2=`CE+feature+R2` 的 2x2：

```text
I_s = (R2_s - R0_s) - (R4_s - K0_s)
```

当前 R4 被预注册为单 seed 诊断，因此本阶段只报告辅助证据，不为计算交互量而擅自扩展 R4。

## 7. R5：feature、relation 与 logits 三者结合

### 7.1 配置与 seed=42 结果

R5 已按门控协议完成 `seed=42`：

```text
R5 = CE
   + warmup * (
       1.0 * feature MSE
       + 0.3 * R2 spatial relation MSE
       + 0.5 * logits KL(T=4, including T^2)
     )
```

命名为 R5 的理由是它在 R 组筛出的 R2 空间关系基础上加入 K 组已锁定的 logits KD；它属于 R 组的跨损失候选，不属于原 scratch K0-K3 2x2。R5 应在 R 组方案中补充完整的 logits 定义、权重、梯度门和停止条件。

| 对比 | mIoU | mAcc | pixel Acc | small-object mIoU | boundary F1 |
|---|---:|---:|---:|---:|---:|
| R5 `seed=42` | `0.573653` | `0.653850` | `0.929604` | `0.489157` | `0.456676` |
| R5-R2 `seed=42` | `+0.033964` | `+0.046261` | `+0.011740` | `+0.049048` | `+0.015411` |
| R5-K3 `seed=42` | `+0.019663` | `+0.035630` | `+0.001854` | `+0.039875` | `+0.012703` |

R5 的 total auxiliary/CE effective gradient ratio 最大值为 `80.03`，但连续超过停止阈值 2 倍的记录数最大为 1，没有触发预注册的“连续三次超过 2 倍”停止门。由于 R5 只有一个训练 seed，以上增益仍是单 seed 结果。

### 7.2 R5 能回答什么

R5 至少提供两个受控增量：

| 对比 | 唯一新增项 | 回答的问题 |
|---|---|---|
| R5-R2 | logits KD | logits 在 `feature+R2` 上是否仍有增量 |
| R5-K3 | R2 relation | 空间关系在 `feature+logits` 上是否仍有增量 |

K 组已显示 K3≈K2，即 feature MSE 没有在 logits KD 上提供可测 mIoU 增量；R 组又显示 R3<R2，即 R1 没有在 R2 上提供增量。R5 的单 seed 结果说明 logits KD 在 `feature+R2` 之上仍有明显增量，但这不等于三类知识的收益可以线性相加。

### 7.3 启动与停止条件

1. R5 `seed=42` 已完成；如作为最终候选，后续补 `seed=3407/260805`，复用对应 shared scratch init、batch 顺序、80k 预算、T1 和 A0 PCA；不得从 K4/A0 checkpoint 初始化。
2. feature、R2、logits 沿用各自已筛选定义和权重，不在第一次 R5 中联合调参。
3. 记录三项对共同 OS=16 tap 的有效梯度范数、两两 cosine 和总辅助/CE 比例；若总辅助梯度连续三次超过 CE 的 2 倍则停止检查。
4. R5 已满足 seed=42 门槛：相对 R2 的 mIoU 增益 `+0.033964`，逐图 paired-bootstrap 95% CI 为 `[+0.025654,+0.042453]`，且没有触发梯度停止门。
5. 若需要把 R5 作为最终主模型，建议补 `seed=3407/260805`；若当前目标是完成 R 组机制筛选并进入 D 组，R5 的三 seed 不是进入 D 组的前置条件。

注意：R5 `seed=42` 的 mIoU `0.573653` 与 K4 三 seed均值 `0.57049` 接近且略高，但 K4 是 A0 分阶段初始化后再训练 80k，R5 是 scratch 训练协议；二者只能作描述性上下文，不能据此宣称 R5 优于 K4 或将差异归因于某个 loss。

## 8. 三 seed 扩展与进入 D 组决定

### 8.1 推荐的最小运行集合

| 优先级 | 实验 | 当前决定 | 新增运行 | 原因与停止条件 |
|---|---|---|---|---|
| P0 | R2 `lambda=0.3` | **已完成** | `42/3407/260805` | mIoU `0.53275 ± 0.00601`；相对 K1 三 seed差值三次均为正 |
| P0 | R3 | **已完成** | `42/3407/260805` | mIoU `0.52839 ± 0.00347`；R3-R2 三次均为负，未显示互补 |
| P1 | R5 | **seed=42 已完成；三 seed 可选** | 当前 1 个运行 | R5-R2 mIoU `+0.033964`，paired CI 完全高于 0；若作为最终主候选则补另外两个 seed |
| 不扩 | R1 `lambda=0.03` | **停止当前配置** | 0 | R1-R0 paired CI 跨 0，后期 relation/feature 比例低于 `0.05`；不满足原计划扩展门 |
| 不扩 | R4 | **保持诊断单元** | 0 | 原计划明确为单 seed、非主候选；不因结果事后改变协议 |
| 不重跑 | R0 | **引用 K1 三 seed** | 0 | R0 seed=42 已与 K1 完全等价；R0 的其余 seed 可由同协议 K1 提供锚点，避免重复计算 |

R2/R3 的预定三 seed扩展已经完成，R5 的 seed=42 门控也已通过。因此，**R 组没有必须补充后才能进入 D 组的实验**。建议直接进入 D 组；若论文需要把 R5 声明为最终稳定主模型，再补 R5 的 `seed=3407/260805`，这属于最终候选复验，不改变 D 组启动决定。

如果跨图关系本身成为论文核心问题，应先登记 R1 的单变量权重校准或更大物理关系 batch，而不是直接为当前 `lambda=0.03` 补 seed。由于这属于看过 seed=42 结果后的新协议，必须明确标注为探索性扩展，不能继续称为原计划验证。

### 8.2 三 seed 后的统计口径

- R2、R3 使用 `42/3407/260805` matched seeds，与对应 K1/R0 锚点共享初始化与 batch 顺序；
- 报告 mIoU、mAcc、pixel accuracy、small-object mIoU、boundary F1 的 `mean ± sample std`（ddof=1）；
- 对每个 seed 的 445 张 dev 图像执行 100,000 次 paired bootstrap；
- 报告 R2-R0、R3-R0、R3-R2 的逐 seed 差值及 CI；
- R5 当前只有 `seed=42`，其与 R2/K3/K4 的比较均须标注为单 seed或非配对描述性比较；
- 不以单个最佳 seed、单个 best checkpoint 波动或 test_local 结果决定是否继续调参；
- `test_local` 继续保持最终留出，直到候选、权重和模型选择规则全部冻结。
